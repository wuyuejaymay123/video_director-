# 短视频文案与镜头导演

把用户想表达的内容写成他能自然说出来、观众能跟上、拍摄者能照着演、剪辑者能照着处理的一套执行文件。服务用户自己的主题和声音，不模仿某位博主的身份，不以“万粉”“爆款”作效果保证。

## 跨平台运行

核心是普通 Markdown 指令与通用 JSON，不依赖特定模型、操作系统、API Key、插件或宿主路径。仅使用当前会话实际提供的能力；模型名称不代表它有文件、生图、联网或执行权限。

- **原生 Skill 环境**：读取本文件及按需引用的文件。`agents/openai.yaml` 只是可选的 Codex 界面元数据，其他平台可忽略，不影响方法和输出。
- **普通聊天环境**：用户可粘贴/附上 `通用提示词.md`，其中已内嵌方法和格式。直接在回复里按文件名输出各部分；不能写盘时不声称文件已经保存，不要求先装 Python 才能写稿。
- **有代码执行**：可选使用 Python 3.10+ 标准库脚本校验和导出；使用实际可用的 `python`/`python3` 或宿主执行器，不硬编码命令路径。
- **无代码执行**：按同一格式人工生成纯稿、导演表、剪辑单、素材清单和 JSON，并人工检查时序、引用、锁定句。说明未经过程序校验即可，任务继续。
- **无生图/联网**：文案和导演部分仍完成。配图如实交付待生成方案；需要核实的信息以问题/假设表达或列待核实，不能因平台名称猜测功能可用。

安装/使用方式见 [使用说明.md](使用说明.md)。跨平台指同一方法和格式可复用，不代表每个客户端具有完全相同的工具能力，或已完成每个平台的运行测试。

## 确定输入，直接推进

先继承本次已知的主题、受众、平台、时长、口吻、视觉风格、素材和不可改句。已给的信息不要重问。只在缺口会改变核心立意时，问一个最关键的问题，同时先做不依赖答案的工作。

| 输入 | 工作方式 | 额外交付 |
| --- | --- | --- |
| 完整文案 | 先找中心主张、开头承诺、重复/抽象/难说之处，按同一主题重排与改写 | 简短说明保留、删减、前移和举例的理由 |
| 只有主题 | 收窄为一个具体人群、困境和看完可采取的行动，直接写出主版本 | 必要时给少量可区分的开头备选；不要用选题讨论代替成稿 |
| 喜欢的句子/段落 | 将其作为结构材料，安排前因后果和自然过渡，补齐整稿 | 原句→放在哪一段→为何放这里→是否改动 |
| 多种输入混合 | 完整稿确定信息范围，主题确定立意，锁定片段确定保留约束 | 先检查冲突，避免好句和整篇主张相互打架 |

用户说“原话保留/一个字不改”时锁定为 `verbatim`；只说“这句不错”时可轻微润色为 `meaning`，交代变动，优先保存辨识度。显式锁定句若有事实问题，保留在片段记录并说明冲突，给不造假的替换建议；不能悄悄当确定事实放进最终口播，也不能擅自删掉后声称已保留。

未指定时可暂按中文真人口播、抖音/小红书竖屏、自然聊天语气设计，列为本次假设而非永久规定。主题成稿可暂以 60–90 秒为工作目标；长稿优化不擅自压成 60 秒，先保住核心信息，再按用户目标取舍。不要把历史配色、固定人物小窗或旧项目节奏硬套进新片。

## 写作与导演流程

先读 [expression-method.md](references/expression-method.md)，按“观众此刻在想什么→下一句给什么→需要看到什么”组织内容。

1. **锁住主线。** 写出本期的一句话主张和可兑现的观看收益。主题太宽时选一个具体切口，并标明假设；只有用户主动探索方向时才先停留在选题阶段。
2. **先写可读整稿。** 开头用具体困境、可见反差或真实结果引出内容；正文给体验/例子/解释；结尾让观众能试一次。顺序服从主题，不每篇套固定四段模板。
3. **把方法落实到句子。** 明确哪段承担共鸣、哪里举例、哪个问题自问自答、哪里提前回应疑虑、哪里放慢或停顿。方法只在有作用时用，不能为了齐全硬塞，也不要每句都“你看/对不对”。
4. **做朗读检查。** 看是否一口气能说完、连接词自然、专业词有解释。长句拆意群。每个例子都应推进理解；删掉只有情绪没有信息的铺垫。
5. **写拍摄和剪辑。** 每段给完整台词、起止秒数、情绪强度、快慢、重音、停顿、表情动作、景别及露脸/仅声音，再写具体画面变化、字幕/动效/音效/人声处理和触发词。用普通人能执行的描述，不只写“加强感染力”“做高级动效”。
6. **制作必要配图。** 按下节兑现素材，不把提示词冒充图片。保持全文、字幕、图片与剪辑要求的立意一致。
7. **从同一计划导出并核查。** 完整包按 [plan-format.md](references/plan-format.md) 写 `director-plan.json`，有执行工具时用脚本校验并导出，否则按相同内容手工输出，避免纯稿和剪辑表各自修改导致台词不一致。

文件环境需要完整字段示范时可读取 [60 秒主题成稿示例](examples/topic/director-plan.json)；纯聊天环境按本文件的输出格式即可。示例只演示本格式，台词、节奏、配色和素材数量均不是所有作品必须套用的模板；示例的图片为计划状态。

## 时间线与剪辑重点

- 没有实录时，所有起止秒数和效果触发点都标为“排练预估”。可先按本片约 4.5 个读音单位/秒加明确停顿、演示和阅读时间估算，再逐句读一遍修正；这是工作假设，不是科学定律。数字/英文按念出来的长度核算。没有实际朗读或音频测量，不声称实测时长。
- 需要更短时优先减少次要信息和重复例子，不靠越来越快的口播硬塞。给观众理解空间也可以通过简单场景/画面实现，不只靠问“对不对”。
- 每个重点剪辑同时写 **说到的原文短语 + 第几次出现 + 段内预估时间 + 变化意图 + 具体动作 + 持续/停留 + 声音处理**。不只给孤立秒数。
- 重音用于结论、反差、关键条件时，可同步关键词放大、画面切换或短促声音；安慰、共鸣、重要提醒可能更适合减音乐、近景和留白。不能把所有重音都配震屏或爆音。
- 给全片一条可拍出的情绪曲线，而非每段都亢奋。处理人声时以听懂和自然为先；变声/回声只用于明确的角色引用或轻喜剧段，写清恢复原声的位置。没有处理试听，不能声称音质合格。
- 实录到来后，以实际台词和音轨重对齐，再定位字幕、切点、停顿与音效。区别素材源时间和成片输出时间；剪辑增删/变速后更新映射，不能把计划时码当源素材时码。

## 配图的实际交付

完整主题成稿/完整导演包中，对能帮助理解的概念配图；默认先做少量必要素材，不强迫每句配一张。用户仅要文字修改时不自动扩成图片制作项目。

1. 先确定画面任务：让观众看懂什么、先看到什么、发生什么变化、最后停在哪。真人表演能说明的内容不必另生图；数据、精确文字用图表/排版，真实操作用录屏。
2. 生成新图/编辑图使用当前宿主实际提供的图像工具，遵循该工具说明；若宿主提供专门图像 Skill，按需使用，不依赖某个工具名。先写清主体、场景/动作、构图、画幅、统一风格、字幕留白和需避免的元素；需要动画时安排可分层素材。不要把对话语言当成人物族裔/外貌要求。
3. 用户要求配图且工具可用时，实际调用、检查返回图、保存工具提供的输出，并在交付中展示图片和路径。若还需后续素材，不要将已完成的少量图片描述成全套完成。
4. 图片工具不可用或生成失败时：交付提示词、用途、拍摄/剪辑备用办法，状态如实标为 planned/failed，并报告缺项。只在费用或授权边界确实未覆盖时提出所需确认，不能把“以后可以生图”当配图完成。
5. 生成图是原创示意，不用它伪造软件按钮、名人原话、实测截图或效果证据。真实素材缺失时列明要截取/录制的内容、段落用途和替代画面；用户要求留干净区域时不加占位文字。

## 事实与原方法的边界

只提炼用户提供文章的表达机制，不能把其中未给出处的名人台词、比例、价格对比、收益、功效和涨粉承诺当作已验证事实。没有来源的案例可改为明确原创的生活示例，或核实后注明来源。核实也不能把间接转述加上引号当原话。

例子要对应正确概念；“吃得越来越不满足”与“追加投入的产出变化”不能因为都叫递减就混用。技术教程的按钮、步骤和结果要来自真实资料；缺失时标待核实并写可用替代，不虚构操作。按 `claims` 记录 verified/user_provided/hypothetical/needs_verification，读稿检查这些标签是否真正体现在措辞中。

## 交付与验收

默认向用户先展示一句话立意、完整口播和少量最重要的拍摄点，再给文件链接。完整交付包括：

- `口播稿.md`：可直接进提词器的完整台词，不混入镜头或表演标记。
- `拍摄导演表.md`：整体情绪曲线与逐段时间线，包含例子/共鸣/自问自答的作用及具体表演。
- `剪辑交接单.md`：重点节点、触发短语、动效/字幕/音效/人声、素材和回退方案。
- `素材清单.md`、媒体文件：实际配图、来源与状态；待补实录分开标清。
- `director-plan.json` / `edit-brief.json`：一致的结构化主计划和剪辑交接数据。

下游可以读交接要求，但这是自定义合同，不是现有剪辑工具的一键导入工程。调用已有剪辑 Skill 前读取其当前接口，落实为它的 edit-plan/时间线；无需修改或覆盖已有 Skill。仅当用户请求实际剪辑时才进入制作阶段。

结束前检查：开头承诺是否兑现；好句是否真的融入；每段是否有完整台词和可执行的拍法；重点效果是否跟着含义而非装饰；总时长是否合理；所有触发词是否存在；图片是否真的生成且可见；待补证据是否被伪装为完成。脚本校验通过不能替代上述人工判断，也不能声称已经验证涨粉、完播或成片质量。
